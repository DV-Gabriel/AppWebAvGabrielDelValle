# 2026-10-31

## Fix HTTP 403.14 (directory listing) al entrar a la raiz del sitio

- Causa: el proyecto no tenia documento por defecto (`Default.aspx` no existia) y la URL
  `http://localhost:16854/` se resolvia como directorio -> DirectoryListingModule.
- Solucion:
  - Nuevo `Default.aspx` + `Default.aspx.cs` + `Default.aspx.designer.cs`: pagina de entrada
    que redirige a `Login.aspx` si no hay sesion, a `DesktopAdmin.aspx` solo si el usuario es
    admin y la pagina existe, y si no a `Songs.aspx`.
  - `Web.config`: se agrego `<system.webServer><defaultDocument>` con `Default.aspx` primero
    y `Login.aspx` como respaldo. Tambien se agregaron `<location>` con `allow users="*"`
    para `Login.aspx`, `SignUp.aspx`, `Logout.aspx` y `songFiles` (con `deny users="?"`
    global el login podia quedar bloqueado).
  - `Web.config`: se agregaron `SongUploadFolder=~/SongFiles` y `MaxSongFileSizeMB=25`
    que consume la BLL.
  - `DAL/Song.cs`: la cadena de conexion ahora intenta `PoliMusicDB` y cae a
    `BDD_PoliMusicConnectionString` (la que ya existia en el proyecto).
  - `WebAppPoliMusicV2.csproj`: se reincorporaron `Default`, `Songs`, `PlayCounter` y las
    clases `Entities/Song.cs`, `DAL/Song.cs`, `BLL/Song.cs` (el csproj habia vuelto a la
    version que solo compilaba `AssemblyInfo.cs`).

## Fix error 40 de SqlClient (servidor no encontrado)

- Causa real: la cadena decia `Data Source=localhost:14333`. SqlClient no acepta `host:puerto`;
  toma todo como nombre de servidor y falla con "error 40 - canalizaciones con nombre".
  El puerto va con COMA: `Data Source=localhost,14333`.
- La BD NO esta en una instancia local: SQL Server corre en Docker
  (contenedor `sql-server2025`, imagen mcr.microsoft.com/mssql/server:2025-latest,
  publica `0.0.0.0:14333->1433`). Los servicios `MSSQLSERVER` y `MSSQL$SQLEXPRESS02` estan detenidos.
- Verificado con System.Data.SqlClient: conecta OK a BDD_PoliMusic (version 17.0.5005.3),
  TBL_SONG tiene 5 filas y la consulta del DAL (con subconsultas de artista/album) corre bien.
- Usuarios en TBL_USER: `userNormal` y `userAdmin` tienen la contrasena en texto plano
  ("12345678"), por eso el login falla con ellos. Solo `gabriel.dv.epn` tiene el SHA1 correcto
  de "12345678" -> se cambio el prellenado de DEBUG en `Login.aspx.cs` a ese usuario.
